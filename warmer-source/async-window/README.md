# Asynchronous WARMER window coordination — research

This folder contains a host-tested state machine, not a vehicle mod, APK or installer. It performs no Android or vehicle I/O. It is not wired into the existing hook or OEM recovery.

The previous research overlay calls `WindowManager.addView()` on the main thread and immediately requires `view.getWindowToken()` to be non-null. In stock Android 4.4, `getWindowToken()` obtains the value from `View.mAttachInfo`, which is set in `dispatchAttachedToWindow()`; that callback runs during the first `ViewRootImpl.performTraversals()`, which is scheduled for a later traversal. Therefore an immediate check can fail before the first traversal even after a successful `addView()`. The head unit's OEM framework may differ, so this remains a source-level finding rather than a measured device result. References: [AOSP 4.4 View](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-4.4.4_r2/core/java/android/view/View.java), [AOSP 4.4 ViewRootImpl](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-4.4.4_r2/core/java/android/view/ViewRootImpl.java).

`AsyncOpenCoordinator` models the alternative: obtain a panel object, schedule attachment and an asynchronous timeout, then suppress one OEM request only if the caller can confirm suppression. On a later attachment/draw callback the backend must prove the same session, safe display and panel visibility. Failure or timeout after a confirmed suppression disposes the panel and attempts OEM recovery once, only if the supplied recovery guard permits it. Normal user close does not reopen it. A thrown skip operation has ambiguous effect and must not trigger a duplicate original call. Every callback must run on the same UI thread, and owner/session identity is pinned per operation.

The model cannot prove CarPlay video surface z-order, actual control state or OEM Binder behavior. A new attach callback alone is not proof of a visible or usable panel. No production implementation of those proofs, callback hookup, `replace` hook declaration, journaled map ownership, OEM `mD()` recovery, or vehicle installer is provided here. This must not be installed on the vehicle as a complete WARMER solution.

Run `python3 neev-carplay/improvements/20261110-warmer-research/async-window/run_tests.py` for ordering, delayed attachment, user close, timeout, exception, safety and owner/session cases.
