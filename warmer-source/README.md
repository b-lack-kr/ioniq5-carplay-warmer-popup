# WARMER 오버레이 실험 후보

한국 아이오닉 5 NEEV 260902에서 수집한 순정 Climate 앱에 맞춘 **실차 미검증 실험 후보**입니다. HMG-API 설정의 `CarPlay WARMER 화면 위 표시 (실험)`은 기본적으로 꺼져 있습니다. 조건을 확인하지 못하면 순정 WARMER 처리를 유지합니다. 동작 전제와 미해결 사항은 [CANDIDATE_STATUS.md](CANDIDATE_STATUS.md)에 정리했습니다.

설정을 켜면 OEM `dipo` Binder에서 세션 활성 상태 4와 유선/무선 모드 1·2를 두 번 확인합니다. DiPO 전면, IGN, 화면, 통화, 후방 카메라와 다른 팝업 상태 및 USM Binder를 함께 확인합니다. 사용자 차량의 Climate 프로세스에 Binder 접근 권한이 있는지, 비정상 종료 후 서비스 상태가 즉시 정리되는지는 아직 검증하지 못했습니다. 상태가 없거나 일치하지 않으면 순정 창으로 넘어갑니다.

순정 전면 레이아웃은 452×414dp, 후석 옵션이 감지되면 후석 포함 레이아웃을 648×414dp로 사용합니다. 앞·뒤 좌석의 열선과 지원되는 통풍, 핸들 열선은 순정 USM 요청과 상태 콜백/캐시를 이용하는 후보입니다. 창의 실제 위치·테두리, 조절 결과, MICOM의 상태 최신성과 CarPlay 영상 위의 표시 여부는 실차에서 확인해야 합니다. Binder가 정상 반환됐다는 것은 하드웨어가 실제로 동작했다는 확인이 아닙니다.

차량 상태 읽기와 버튼 명령은 제한된 단일 워커에서 처리합니다. 새 상태가 아직 준비되지 않거나 조회가 지연되면 이전 화면을 잠시 표시하되 조작은 막습니다. 핸들 DOWN 실행 중 창을 닫으면 같은 워커가 DOWN 반환 이후 UP을 한 번 시도합니다. 프로세스 종료나 Binder 무한 대기 시 UP 전달은 보장되지 않습니다. 순정 팝업 복구는 독립된 제한 시간의 안전 상태 조회가 성공하면 한 번 시도하며, 그 조회가 멈추거나 안전 조건이 불명인 경우 강행하지 않습니다.

`python3 test.py`, `python3 test_map.py`, `python3 test_async_overlay.py`, `python3 installer/test_prepare.py`는 로컬 모의 시험입니다. `python3 build.py`는 주요 시험 실행 후 Android API 19 대상 payload를 컴파일·서명하고 서명을 확인합니다. 차량 접속은 하지 않습니다. 별도 설치기와 ★ 설정 패키지의 맵 소유권 처리 및 차내 설치·삭제는 별도로 검증해야 하며, 이 디렉터리의 signed payload만 차량에 직접 복사하지 마세요. `build/research-author.key`는 로컬 서명 키이므로 배포 파일에 넣지 않습니다.
